storm-desk privacy

storm-desk runs on Atlassian Forge, inside your Atlassian site. This page tells you what it stores.

What the app stores

The app stores this in Forge hosted storage for your site:

  • For each new service request: its id, issue key, project key, summary text, created time, and the account id of the reporter.
  • A numeric vector made from the request text (used to find similar requests), with the request id and key.
  • A short marker that says a request was queued for processing.
  • For each storm parent issue the app made: its key, the linked requests (id, key, summary), and the "maybe" requests (id, key, summary, score).
  • A marker per request that says a late request was already handled.
  • A page log of the last 100 actions (time, action text, count).

The summary text and the reporter account id can be personal data. When you use the sample button, the app also creates test customers with example.com addresses in your Jira Service Management site.

Where the data goes

Nowhere outside Atlassian. The app has no external network permission, and the language models that compare the text run inside the app function. We do not receive your data. We have no server and no database.

How long it stays

  • Requests, vectors and queue markers: removed after 3 hours. The clean-up runs when the next new service request arrives, so the last requests can stay longer on a quiet site.
  • Page log: only the newest 100 lines are kept.
  • Storm parent records and late-request markers: kept until the app is uninstalled. The app has no delete step for them.
  • After uninstall: Atlassian soft deletes the app data and keeps it for the retention period in its own policy (see the Forge data lifecycle page).

How to remove your data

Ask the site admin to uninstall the app. Comments and links the app made in Jira are normal Jira data; the site admin manages them in Jira.

Contact

Use GitHub Issues. Do not put personal data in an issue.
